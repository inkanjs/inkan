# 0.10.0: the same speed, with MCP beside it

0.10 adds the MCP endpoint (`mcp: true`), which is off by default and lives next to the
request path, not on it: one more comparison where the built-in pages are matched, and a
note for the log on requests a tool call sends. `app.inject` lost an extra `await` per
request, which only tests and the in-process bench see. So, as with 0.9, the bench is here
to show that nothing got slower.

## On the GitHub runner, release gate

Three runs of the `bench` workflow (kind http, 15 s per measurement, 3 rounds each) on
2026-11-13, `main` at the MCP merge against v0.9.4 as `inkan-base`: runs 43386839672,
43386844643, 43386849151. The three ran at the same time on three runners; the third
runner was slower overall (node:http at about 45k req/s against 75k), which moves every
server alike, so the scores stay comparable within each run.

| server | run 1 | run 2 | run 3 | median |
| --- | ---: | ---: | ---: | ---: |
| **inkan 0.10** | **93.1** | **89.2** | **89.8** | **89.8** |

## In process

`node bench/inproc.mjs inkan,inkan-base 5` with `MODE=production`, against v0.9.4: 95.8
(geomean of µs per request, lower is faster). Before the `inject` fix the same bench gave
104.4: `drain()` took an `await` per request even without a stream. Almost all of the 4 %
is `inject` itself, which the HTTP bench above does not use.
